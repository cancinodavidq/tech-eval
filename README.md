# Tech Evaluation — AI Architect (MASGlobal)

This repository contains the deliverables for the AI Architect technical evaluation. Each question is in its own folder; the shared input that drove both answers (the Legal Department research brief) lives at the root.

## Deliverables

### [`q1/`](./q1) — Vanilla RAG as the starting point

A written design rationale arguing that the initial RAG architecture should be the simplest system that meets the stated requirements, with an evaluation layer instrumented from day one to drive what gets added next. Includes the supporting architecture diagrams.

- **Read:** [`q1/design_rationale.md`](./q1/design_rationale.md)
- **See:** [`q1/rag_vanilla_final.svg`](./q1/rag_vanilla_final.svg), [`q1/rag_final.svg`](./q1/rag_final.svg), and the drawio source

### [`q2/`](./q2) — RAG Evaluation Pipeline

A production-ready Jupyter notebook that scores RAG outputs on three independent metrics — context relevance, answer faithfulness, and answer correctness — using a cross-encoder, atomic claim decomposition with an LLM judge, and a composite semantic + factual score. The synthetic stress-test dataset is generated by Claude at runtime from a user-supplied domain prompt.

- **Read:** [`q2/README.md`](./q2/README.md) for setup and usage
- **Run:** [`q2/rag_evaluation.ipynb`](./q2/rag_evaluation.ipynb)
- **Example outputs included** so the evaluator can inspect a real run without executing

## Shared input

- [`Legal_Department_RAG_Research_Brief_EN.docx`](./Legal_Department_RAG_Research_Brief_EN.docx) — the research brief from MASGlobal that drives both deliverables (domain, requirements, constraints).
